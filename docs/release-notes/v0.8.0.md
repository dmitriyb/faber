# faber v0.8.0

The box shares no path with the host any more. Everything faber used to bind
mount into a container — the engine binary, the hook scripts and skills, the
result directory, the agent socket, the template volumes, the check remote —
now reaches the box as image content, as a stream, or as a docker volume.
A docker daemon with userns-remap runs faber unchanged, and so does macOS
Docker Desktop without any host-side knob. `docs/deploy.md`, "Host
filesystem and user namespaces", has the details and the upgrade sequence.

## Rebuild your images

`faber-box`, the hook scripts and the skills tree are baked into every
template image, and their bytes are part of the image tag. Run `faber build`
after upgrading faber and after editing a hook or a skill; the run preflight
says so when a tag is stale. `faber resume` refuses a run whose hooks changed
since it started (`--fresh` starts over). The faber↔faber-box contract is
now v3: an image built by an earlier faber is refused at the start of its
first step with "run faber build", never partway.

## What changed for you

- **Results travel over the box's stdout.** The result directory is a tmpfs
  the box ships to the host when the step ends. `output.log` is live as
  before; the hooks' events file is streamed line by line; `--sessions`
  transcripts arrive when the step ends (a container killed mid-step loses
  its transcript). Interactive re-entry receives the handoff and the saved
  transcript into the box instead of mounting them.
- **The agent reaches the box over a relay.** The signing proxy stays on the
  host; `faber-box relay`, started through `docker exec`, serves it on a
  socket inside the box. `agent_socket_group` in `host.json` is retired and
  a file still naming it is refused with a message saying so.
- **Template volumes are docker named volumes.** `run.volumes: {<name>:
  /container/path}`; the daemon creates `faber-<project>-<name>` on first
  use and keeps it across runs. A host path as a key is refused at
  `faber validate` — there is no migration shim; move what the box needs
  into the volume once. `faber volumes` lists a project's volumes and
  `faber volumes prune` removes them (refused while a run is live).
- **`faber check` seeds its remote into a volume** from a `git bundle` of
  the working directory's repository; `--keep` keeps the volume beside the
  journal directory and prints both.
- **The run user exists inside the box**: the preamble writes its passwd and
  group entry, which OpenSSH needs and a toolset image never carried.

## Timing is unchanged

The result files are written at the same phase as before; only the transport
moved. A step's record, handoff and usage sidecar land under the same paths
in the run directory, and the live view reads them as it did.
